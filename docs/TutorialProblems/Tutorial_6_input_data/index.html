    Drag anchor - input_data_AC14_dr32.json¶

    The complete input_data_AC14_dr32.json for Tutorial 6, also included with MPM3S in validation_data_and_jsons. Every key is described on the input_data.json file format page. Click the numbers in the file to see what each part does, with links to the tutorial's explanation and to the format reference for those keys.

    It needs the anchor geometry - AC14_fluke_rot20.stl, AC14_fluke_rot20_mesh.txt, AC14_shank.stl and AC14_shank_mesh.txt - in the same folder; all four are in validation_data_and_jsons.

    1. Runs on an NVIDIA GPU, as the reference simulations were run. Machine → · GPU →
    2. Gravity in \(-z\); the background mesh is a \(204.8\) m cube. Domain → · Domain →
    3. One \(18.123\) m layer of Willam-Warnke sand at \(D_r = 32\%\), \(120 \times 10\) m, with \(2.0\) m base elements. Material points → · Material points →
    4. One system: the anchor. Rigid body: points → · Rigid bodies →
    5. Moves the anchor \(1\) m in \(+x\), so it does not overhang the soil. Rigid body: points → · Rigid bodies →
    6. Point 1 is the fluke, point 2 the shank and point 3 the pull point. Rigid body: points → · Points →
    7. The hinge, the opening-angle stop and the pull line. Rigid body: constraints → · How the constraints work →
    8. The fluke, turned \(20^\circ\) tip-down, and the shank. Rigid body: geometry → · STL files →
    9. A marker at the fluke tip, written to rigid_body.csv. Rigid body: geometry → · Tracked nodes →
    10. Coulomb friction, \(\mu = 0.45\). Contact → · Contact →
    11. Three stages, run in order. Stage 1 → · Analysis stages →
    12. Stage 1, static, anchor off: gravity ramped up over 5 load steps on a uniform mesh. Stage 1: initial stresses → · Adaptivity →
    13. Stage 2, dynamic, \(1\) s: the anchor is placed on the surface and settles, and the boundary track starts. Stage 2: settling → · Boundary track →
    14. Stage 3, dynamic, \(800\) s: the pull point moves \(0.004\) m every \(0.04\) s step, dragging the anchor \(80\) m. Stage 3: drag → · Rigid body boundary conditions →
    15. Tolerance \(10^{-6}\) and 20 iterations, with ghost stabilisation of poorly filled elements. Solver → · Solver →
    16. VTK files every \(1\%\) and CSV files every \(0.25\%\) of each stage's steps. Output → · Output →
